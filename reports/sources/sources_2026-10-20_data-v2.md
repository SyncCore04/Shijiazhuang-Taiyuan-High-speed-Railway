## 1. 为什么换源

data-v1 的时刻来自去哪儿/携程等第三方聚合页，README 与契约里一直标注「全部需 12306 官方复核」。
本批改为**直接调用 12306 官方前端页面所使用的接口**，与浏览器 F12 里看到的请求完全一致，不再经过第三方聚合。

差异对比结果（`reports/manual_review/data-v1_to_v2_diff.md`）：

- v1 的 92 车里，**88 车在 v2 中同编号可比，逐站到发时刻 100% 一致**；
- v2 多出 69 个车次（v1 未采到的 K/T/Z 普速、部分 D/G/C）；
- v1 独有 1 车：D918（12306 显示 2026-10-20 当日不开行，v1 的 uncertainties 也记载其 10/20–22 停运）；
- 3 处仅编号不同：G1861→G1864、G1955→G1958、G2637→G2640（站表与逐站时刻完全一致）。

结论：v1 已采到的车次数据本身准确，v2 的主要价值是**补全覆盖范围 + 去掉“需复核”这一层不确定性**。

## 2. 采集通道（与前端页面一致）

| 步骤 | 请求 | 用途 |
|---|---|---|
| 1 | `GET https://kyfw.12306.cn/otn/leftTicket/init?linktypeid=dc&fs=太原,TYV&ts=石家庄,SJP&date=2026-10-20&flag=N,N,Y` | 建立会话，拿 `JSESSIONID` / `BIGipServerotn`，并从页面读出 `CLeftTicketUrl` |
| 2 | `GET https://kyfw.12306.cn/otn/leftTicket/queryG?leftTicketDTO.train_date=2026-10-20&leftTicketDTO.from_station=TYV&leftTicketDTO.to_station=SJP&purpose_codes=ADULT` | 余票查询，返回区间内车次、始发/终到站、到发时刻、历时 |
| 3 | `GET https://kyfw.12306.cn/otn/czxx/queryByTrainNo?train_no=…&from_station_telecode=…&to_station_telecode=…&depart_date=2026-10-20` | 按物理交路拿**全程经停站**到发时刻 |
| 4 | `GET https://kyfw.12306.cn/otn/resources/js/framework/station_name.js` | 电报码 → 中文站名（3404 站） |

- 本次 `CLeftTicketUrl` 返回 **`leftTicket/queryG`**（该值由 12306 动态下发，脚本自动解析，不写死）。
- 请求头带常规浏览器 UA、`Referer` 指向 init 页；**未绕验证码、未登录、未高频请求**（每请求间隔 1.1–1.5 秒）。
- 原始响应全部留证在 `data/raw/_12306_raw/2026-10-20/`（`leftTicket_*.json` 20 个 + `circuit_*.json` 159 个），只读，不参与前端加载。

| 太原/太原南 ↔ 北京西、北京丰台（8 向） | 51–54 / 向 | **补「走廊内通过不停」的标杆车**，见 §2.2 |

按 `train_no`（物理交路）去重后得到 **159 个交路**，逐车查 `queryByTrainNo`；
**2 个跳过**：K603/K604（北京西—灵丘—原平—太原，走京原线，不经石太）。

### 2.2 为什么补「太原 ↔ 北京」这 8 组 OD

G380（太原 08:33 → 北京西 10:38，2 小时 05 分）在石家庄**通过不停**。
12306 余票查询按 OD 售票，石家庄不停就不卖「太原→石家庄」的票，该车次**不会出现在短途查询结果里**——
这是 OD 枚举法的系统性盲区：所有走廊内通过不停的车都会被漏掉。

补充判据：北京西、北京丰台只能从石家庄方向接入，故「太原/太原南 ↔ 北京西/北京丰台」的车必然经石太客专。
两个过滤器保证不误收：

1. **电报码卡死**：12306 会把「北京西」按「北京」城市聚合，连带返回到北京北、清河的车（那些走大西+京张，不经石太）。
   因此只保留实际上/下车站电报码为 `BXP` / `FTP` 的记录。
2. **京原线剔除**：同 OD 里的 K603/K604 走京原线（灵丘、五台山北、繁峙、代县、原平、忻州、阳曲），
   站表含这些特征站且不含石家庄/阳泉北的，直接跳过。

最终补回 **G379（北京丰台 08:56 → 运城北，太原南通过不停）、G380（太原 08:33 → 北京西）** 这一对标杆车。

## 3. 字段映射

### 3.1 余票接口（`result` 每行按 `|` 分割）

| 索引 | 含义 | 本批用途 |
|---|---|---|
| [2] | `train_no`（物理交路号） | 查 `queryByTrainNo` 的主键 |
| [3] | 车次号 `station_train_code` | 车次号候选 |
| [4] / [5] | 始发站 / 终到站电报码 | 与全程站表首末站交叉核对 |
| [6] / [7] | 本区间上车站 / 下车站电报码 | 判断该车次号在走廊内的位置 |
| [8] / [9] | 上车站发车 / 下车站到达 | 与 `queryByTrainNo` 同站时刻核对 |
| [10] | 区间历时 `lishi` | 与脚本算出的区间历时逐车核对 |
| [13] | 始发日期 `start_train_date` | 换算 `day_offset` 的基准 |

### 3.2 经停站接口

每行含 `station_name`、`arrive_time`、`start_time`、`stopover_time`、`station_no`；
`arrive_time = "----"` 表示始发站无到达，`start_time = "----"` 表示终到站无出发。
**注意**：`station_train_code` / `train_class_name` 只在交路首行给值，其余行为 `null`，不能逐行判断车次号。

## 4. 三个推断规则（v2 特有）

### 4.1 `day_offset`（跨日）

12306 只给 `HH:mm`，不带日期。脚本按站序推断：

- 相邻站若时刻回落，且「跨日后区段时长」≤ 20 小时，判为跨日 +1；
- 同站 `dep < arr` 且停站时长 ≤ 20 小时，判为停站跨午夜 +1；
- 回退量过大（> 20 小时）视为时刻异常，不跨日。

再用 `leftTicket[13] start_train_date` 换算到**基准服务日 2026-10-20**：
`day_offset = 相对始发日偏移 − (2026-10-20 − 始发日期).days`。

因此 v2 出现**负 `day_offset`**（441 条非零记录中 199 条为负）：这些是 10-19 就从远端始发、
10-20 才经过走廊的长途车（如 D16 成都东 15:37 开）。这是正确的——运行图画的是「10-20 这天在走廊里跑的车」，
而不是「10-20 始发的车」。契约 2.1.0 已放宽 `abs_minute` 可为负。

53 个车次有跨日推断，逐条推断说明写在 `reports/sources/collect_2026-10-20_data-v2.json` 的 `cross_day_notes`。

### 4.2 `direction`

- v1 已收录的车次：**沿用 v1 人工核定方向**（不擅自改口径）；
- v1 没有的新车次：按站序判定——太原侧在前、石家庄侧在后为 `up`，反之为 `down`；阳泉东支线同理；
- 判不出的写 `unknown`（本批 0 车）。

本批 up 76 / down 81。

### 4.3 `train_type`

按车次号前缀判定，与项目既有口径一致：G→高铁、D→动车、C→城际、S→市郊、Z→直达特快、T→特快、K→快速。

> 12306 的 `train_class_name` 对 C 字头返回「动车」、对 S 字头返回「快速」，与项目口径不符，因此**前缀优先**，前缀不明时才回退到接口分类。

## 6. 已知限制

1. **停站跨午夜的 4 车无法绘制**：`K214`（石家庄北 23:57 到 / 00:07 开）、`K546`、`K892`、`T175`。契约每站只有一个 `day_offset`，同一站的到达与出发跨日时无法同时正确表达，故阻断而非改时刻。
2. **同一物理交路只录一个车次号**：12306 的 `train_no` 是车底交路，一趟车中途换号（如 D1152→D1153）。本批按「优先沿用 v1 编号，否则用交路首行始发号」只录一条，另一编号写入 remark 的「同一物理交路另含车次号」。
3. **12306 只返回营业停站**，不返回通过站；相邻营业站之间的实际经由由线路骨架 BFS 路径绘制。
4. **`km` 全为 null**：12306 前端不提供里程。
5. **开行状态以 2026-10-20 当日查询为准**：D918 当日不开行，故不在本批；隔日/临客可能随日期变化。
6. **G379/G380 在走廊内无停站**（石家庄通过不停），数据完整收录可查时刻，但运行图/线路图没有可画的线段——它们本来就是「穿过走廊但不上下客」的标杆车。
